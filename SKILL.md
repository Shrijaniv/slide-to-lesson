# Slide to lesson

The teaching is the product. Write the explanation from the actual slides, then choose visuals that help a learner build a correct mental model. The builder uses the original slides by default and can substitute a silent animation for any slide. Voice generation remains separate so users can choose a local or external provider.

## Workflow

1. Get the user's slide deck. For PowerPoint or Keynote, use an available local export tool to create a PDF; otherwise ask for a PDF export. Work from the actual slides, not filenames or a summary.
2. Inspect every slide visually and extract its text. For each substantive slide, identify what a learner must understand, what the slide leaves implicit, and likely confusion. Build the explanation around the causal steps, a concrete example or worked calculation, and a short check or comparison that lets the learner apply the idea. Define terms when first needed; connect the slide to what came before and what follows. Use a general college audience and about 1–2 minutes per substantive slide when unspecified. Avoid padding title, agenda, and references slides.
3. Keep teaching claims grounded. Distinguish an inference from something stated on the slide. Do not invent precise facts, citations, quotations, or research findings. Flag unclear diagrams or equations for review. If slide notes, a textbook, or references are supplied, use them to deepen the script.
4. Add an animation only when motion reveals a change, sequence, dependency, or spatial relationship that the static slide does not make clear. Specify the teaching point, what changes on screen, and the narration cue. Use the original slide or its key labels as context, show one mechanism at a time, and leave a meaningful final frame. A callout, diagram, worked example, or short simulation can be more useful than decorative motion. Preview the animation with the actual narration and correct any mismatch. If no animation is needed, use the slide unchanged.
   For an interactive lesson, place a short concept check after a coherent section rather than every slide. Ask the learner to predict, calculate, compare, or diagnose a misconception using ideas just taught. Use plausible alternatives and explain why the answer follows; avoid trivia and questions copied verbatim from the slide. Quizzes should reinforce learning without blocking a learner who needs to skip.
5. Save the narration as a UTF-8 JSON array with one string per slide, in slide order. Make the full script reviewable before assembly when the content has unresolved technical ambiguity or the user asked to approve wording. Otherwise proceed to the video.
6. Choose a voice route that fits the user's access and quality needs. Mac speech needs no account. Existing audio from any provider works through `--audio-dir`; require exactly one `slide-01.mp3` (or `.wav`, `.m4a`, `.aiff`) through the last slide. External generation needs the user's authorization and credentials; never put a key in the script, log, or output. Whisper and similar tools transcribe speech; they do not synthesize it. If Mac speech produces empty audio, use an available audio route or report the failure with the script preserved.
7. For an animated slide, save a silent `slide-XX.mp4` in a visual directory. It replaces that slide's still image for the narration segment; the builder holds its final frame if it ends early and trims it if it runs long. Author the clip with an appropriate animation tool, such as HTML/CSS, SVG, or HyperFrames when available. Check that any embedded text remains readable at 1280×720. If the animation changes after a particular spoken phrase, align it to the actual audio rather than a guessed words-per-minute rate.
8. Run `python3 scripts/build_video.py <slides.pdf> <narration.json> <output.mp4> [--voice Samantha | --audio-dir <folder>] [--visual-dir <folder>]`. The helper uses Swift/PDFKit and FFmpeg, plus `say` for Mac speech. It writes an MP4 with slide chapters, a transcript, and JSON with measured slide times and visual choices. Report any missing command or audio clip precisely.
9. If interactive checks were requested, save a UTF-8 JSON array of `{ "after_slide": 7, "question": "...", "options": ["...", "..."], "correct_index": 0, "explanation": "..." }` objects. Run `python3 scripts/build_interactive.py <video.mp4> <video-timings.json> <quizzes.json> <interactive.html>`, with HTML beside the MP4. The local HTML player pauses at each checkpoint, gives feedback, and resumes. Keep the MP4 available as a normal noninteractive version; clickable choices cannot live inside an MP4. Deliver the HTML and MP4 together, or package them in one ZIP for sharing.
10. Check that the MP4 contains both video and audio, inspect representative frames including each animation's beginning, active moment, and final hold, and listen to samples from the beginning, middle, and end. For interactive lessons, verify the pause, answer feedback, skip, and resume flow in a browser. Deliver the video, transcript, and optional player. Mention any slide whose explanation relies on an assumption.

Captions are optional. If requested, obtain word timing from the provider or align/transcribe the actual audio; do not spread words evenly across a slide. The builder assembles supplied animation clips but does not create them, an avatar, or independently verified facts. Slide content stays local unless the user authorizes an external service.
